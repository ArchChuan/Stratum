# 平台助手默认模型与配置入口设计

## 目标

Stratum 平台助手默认使用智谱当前主力模型 `glm-5.2`，同时保留租户管理员覆盖默认值的能力。模型配置统一放在
Agent 详情页；Agent 对话页只负责对话和展示运行状态，不再提供独立配置入口。

成功标准：

- 新租户的平台助手默认模型为 `glm-5.2`；
- 历史租户中尚未配置模型的平台助手幂等补为 `glm-5.2`；
- 历史租户已经选择的模型不被默认值覆盖；
- 租户管理员可从平台助手详情页选择任意当前租户可用的聊天模型；
- 非管理员不能修改平台助手模型；
- 对话页不再出现平台助手模型设置按钮或弹窗；
- 未配置智谱凭据时不静默切换 Provider，执行继续明确报告模型不可用。

## 事实与依据

当前平台助手记录位于每个租户 schema 的 `agents` 表，以
`system_key='stratum.platform_assistant'` 唯一识别。普通 Agent 更新接口会拒绝平台托管记录；现有
`GET/PUT /agents/system/settings` 已提供只读设置查询和仅更新模型的管理员接口。前端目前把该专用接口包装在
Agent 对话页的 `SystemAssistantModelModal` 中，而通用编辑页仍调用会被拒绝的普通 Agent 更新接口。

智谱官方模型目录在 2026-07-27 列出 GLM-5.2，并提供专门的 GLM-5.2 迁移指南；本仓库
`pkg/tokenutil/pricing.go` 也已登记 `glm-5.2`。本设计把具体模型 ID 作为经代码审查的产品默认值，不在运行时根据
名称或列表顺序推断“最强模型”。

相关官方来源：

- <https://docs.z.ai/guides/llm/glm-5.2>
- <https://docs.z.ai/guides/overview/migrate-to-glm-new>

Obsidian 中已验证的 Agent Harness 原则要求模型选择与确定性治理边界分离。本设计只调整租户拥有的模型选择，
不会把平台提示词、工具权限、重试或执行控制开放给租户。

## 方案选择

采用“持久化默认值，管理员覆盖优先”：租户 schema 基线负责写入和补齐默认模型，现有专用设置服务负责校验并
保存管理员覆盖值。

不采用运行时动态挑选模型，因为这会使模型在未审计的情况下漂移，并可能覆盖租户管理员的明确选择。不采用仅
前端预选，因为 API、数据库和非浏览器执行仍会看到空模型。

## 后端与数据

在 Agent 领域的共享常量位置定义平台助手默认聊天模型 `glm-5.2`，供应用测试和文档化契约引用。SQL 无法引用
Go 常量，因此 `tenant_schema.sql` 中保留同值字面量，并由 schema 测试逐字验证二者一致。

租户 schema 基线执行两类幂等操作：

1. 新建平台助手记录时将 `llm_model` 写为 `glm-5.2`；
2. 对现有 `system_key='stratum.platform_assistant'` 且 `llm_model` 为空字符串的记录执行条件更新。

条件更新不得覆盖任何非空模型。该变更位于 tenant-only DDL 唯一基线，不新增 public 编号迁移。

现有 `PUT /agents/system/settings` 保持为唯一模型写入口。应用服务继续先读取租户模型目录并调用
`TenantModelValidator`，只有目标模型在当前租户可用时才持久化。目录读取、校验或持久化失败全部向上传播。

平台助手的默认值不等同于 Provider 凭据。若租户未配置智谱，设置响应返回 `ready=false`，执行返回现有的
模型不可用错误；系统不会自动切到其他 Provider。管理员可在详情页选择当前租户已配置的其他模型。

## 前端交互

Agent 列表保持现有编辑入口。`/agents/:id/edit` 加载 Agent 后按 `isSystem` 分流：

- 普通 Agent 继续使用完整 `AgentFormSections` 和普通更新 API；
- 平台助手显示系统内置标识、平台托管说明、当前就绪状态和单个“LLM 模型”选择器；
- 平台助手页面通过 `GET /agents/system/settings` 获取当前值和 `availableModels`，保存时调用
  `PUT /agents/system/settings`；
- 只有管理员路由可进入详情页，保存中禁用重复提交，失败通知不自动消失，成功通知最多显示两秒。

如果默认 `glm-5.2` 不在 `availableModels` 中，页面仍展示当前值并明确标为不可用，同时允许管理员选择列表中的
其他可用模型。页面不开放名称、描述、系统提示词、迭代次数、工具、Skill、知识库或 Memory 配置。

对话页删除 `SystemAssistantModelModal`、设置按钮及对应页面状态。Header 继续显示当前模型；模型未就绪时显示
联系管理员的运行提示，但不提供配置跳转或第二入口。

## 兼容性与权限

API 路径和响应 JSON 形状保持不变，现有客户端无需迁移。普通 Agent 编辑行为不变。平台助手仍由
`system_key` 和后端授权规则识别，前端分流不构成安全边界。

租户角色要求保持现状：settings 查询可用于展示，settings 更新必须通过 `requireAdmin` 和 active tenant 校验。
任何绕过详情页直接调用普通 Agent 更新接口的请求继续返回平台托管错误。

## 测试与验收

后端测试覆盖：

- tenant schema 新建记录的默认模型；
- 历史空模型回填；
- 非空管理员选择不被 schema 重放覆盖；
- settings 更新继续校验租户模型目录并传播目录、校验和持久化错误；
- settings RBAC 与普通 Agent 更新拒绝规则保持不变。

前端测试覆盖：

- 平台助手详情页只渲染模型设置；
- 加载、空目录、当前模型不可用、保存成功和保存失败状态；
- 普通 Agent 详情页行为不回归；
- 对话页桌面和移动视口均不存在模型设置按钮或弹窗；
- 成员仅看到未就绪提示，不能进入管理员编辑路由。

端到端验收使用真实浏览器、API 和测试数据库：创建或升级租户后确认默认值，管理员从详情页覆盖模型，再进入
对话页确认只展示当前模型且没有配置入口。若测试环境没有智谱凭据，验收 `ready=false` 和可见错误边界，不把
缺失凭据当作成功执行。

## 范围外

- 自动跟随未来智谱新模型；
- 自动创建或注入租户智谱 API key；
- 修改普通 Agent 的默认模型或表单；
- 改变平台助手提示词、工具、权限、执行预算或 Provider fallback；
- 删除现有 settings API。
