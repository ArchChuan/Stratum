# Agent 面试库全量重构融合设计

## 目标

`2026-07-23-agent-interview-consolidation-design.md` 定义了增量融合：每日报告按分类并入长期库，只合并互补证据、不重写既有条目。实际运行显示该模型导致库冻结——近期账本 `created=0 updated=0 duplicate=14-16`，文章不随最新网络趋势和仓库代码演进。

本次改造把融合阶段改为**全量重构**：每次融合都结合（1）网络最新热门前沿内容（当日报告）、（2）最新代码实现（仓库变更摘要）、（3）既有长期库，把每个分类文件整体重写为融合、去重、刷新后的版本。禁止把新内容追加到文章底部。

## 非目标

- 不把 `tmp/` 下的本地研究资料改为受版本控制的项目事实源。
- 不自动修改 Stratum 业务代码来落实报告中的建议。
- 不改变固定分类文件集合、README 账本行格式、coverage manifest 格式、inbox/原子发布机制。
- 不迁移 Hermes 调度框架或其他 `tmp/cron/` 任务。

## 全量重构契约

融合 prompt 明确要求：

- **整文件重写**：每个分类文件重写为标准文章结构（`## 0. 分类边界与融合说明` / `## 1. 项目关键知识` / `## 2. 流程与架构图` / `## 3. 热门面试题与结合项目的答案` / `## 4. 趋势与观点` / `## 5. Stratum 可补强点` / `## 6. 跟踪关键词` / `## 7. 参考来源`），禁止在文件末尾追加新内容块。
- **融合去重**：新报告内容并入规范条目并更新 `最近更新`；同一主题全库只出现一次且只有一个主分类；被取代/过时条目压缩或删除，但保留来源追溯（来源 ID/URL、源码路径、关键词）。
- **稳定 ID**：存活主题保留既有稳定 ID，不重编号；仅真正的新主题创建新 ID。
- **对照最新代码**：所有 Stratum 主张对照仓库变更摘要核对，引用当前代码/文档路径；过时或冲突主张显式标注。新日期单独不构成覆盖旧证据的理由。
- **账本与统计**：README 处理账本行格式不变；created/updated/duplicate/unclassified 反映本次重构的真实增减；规则章节声明全量重构语义。

## 仓库变更摘要

脚本在锁与库校验后生成 `OUT_DIR/repo-digest-<run-id>.md`：

- `git log --since=<AGENT_INTERVIEW_REPO_SINCE_DAYS 默认 14> days ago --no-merges` 最近提交（head 限 200）+ 变更文件列表（去重，head 限 100）。
- 摘要路径内插进生成与融合两个 prompt；模型自行读取。
- git 失败时生成含 `digest unavailable` 标记的摘要文件并显式告警（研究输入 fail-open，但部分失败必须暴露在日志）。

## 校验契约兼容

分类文件章节校验从整行精确匹配改为语义关键词匹配：每个分类文件必须恰好有一个标题行包含 `分类边界` / `趋势与观点` / `面试题` / `Stratum 可补强点` / `跟踪关键词` / `参考来源`。新旧版式均通过；2026-08-03 已重构的现网库无需迁移即可通过校验。

固定文件集合同步现网演进：`00-question-bank-index.md`（08-03 手工重构新增的按题号题库索引）加入 `AGENT_INTERVIEW_LIBRARY_FILES` 白名单与 stage 拷贝，但它是索引而非文章，不参与章节、稳定 ID 唯一性与待分类计数校验（`AGENT_INTERVIEW_CATEGORY_FILES` 保持 10 个分类文章）。融合契约要求重构后同步刷新其题号→文档映射与维护说明。

## 执行器：Claude Code

研究/融合执行器从 codex 切换为 Claude Code CLI，模型固定 `deepseek-v4-pro`（env `AGENT_INTERVIEW_MODEL` 可覆盖）。调用形态 `claude -p --model <model> --dangerously-skip-permissions --no-session-persistence`，工作目录通过子 shell `cd "${STRATUM_ROOT}"` 设置（claude 无 `--cwd`）；生成报告通过 stdout 重定向写文件，输出路径经 env `AGENT_INTERVIEW_OUTPUT_FILE` 透传给测试替身（保留 `-o` 参数兼容）。dry-run 用 `command -v` 探测执行器存在性。测试替身 `testdata/fake-codex.sh` 保持确定性输入输出，不依赖真实模型。

## 定时任务数据流（不变部分）

生成阶段写 inbox → 融合阶段在临时目录重构 → 确定性脚本校验（分类白名单、章节、稳定 ID 唯一、账本、待分类计数、coverage）→ 原子发布 → 消费已处理输入。哈希幂等、来源身份冲突 fail-closed、失败回滚与输入保留全部保持。

## 验收标准

- 融合输出中每篇文章是完整重写的融合体：既有稳定条目与新增内容并存，无文件底部追加块。
- 重构后的库通过校验契约（旧版式与新版式 fixture 均验证）。
- 同一内容重复输入第二次不产生内容变化；融合失败时正式库字节不变且输入保留。
- 生成与融合 prompt 都能读到仓库变更摘要；git 不可用时任务告警但不中断。
